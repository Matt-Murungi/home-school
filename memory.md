## Hand-off protocol

**memory.md is committed straight to `main` (message `memory: …`), never inside a ticket PR.** This avoids merge conflicts. Always `git pull` before editing it, commit and push right after. Only one agent works at a time; the main agent waits for the reviewer's verdict before starting the next ticket.
The reviewer verifies in a separate worktree (`git worktree add <scratchpad>/review-<id> <branch>`), never in the main checkout, and removes it afterwards. A PR cannot be approved by its own author on GitHub, so the reviewer posts its review with `gh pr review --comment` and merges with `gh pr merge --squash --delete-branch`.

Each ticket has a block under "Ticket log" with a `Status`:
`todo` → `in-progress` (main) → `ready-for-review` (main) → `changes-requested` (reviewer) → `ready-for-review` … → `merged` (reviewer) | `blocked-foundation-merged`.
Main agent writes: what was built, files, test command + result, which acceptance criteria/edge cases map to which tests, deviations, open questions.
Reviewer writes: commands run, results, criterion-by-criterion verdict, findings, PR number, merge commit.

## Reviewer checklist

1. `git pull` main; read this file and the ticket block; read the issue.
2. Verify in a separate worktree: run the documented test commands from a clean checkout (record the real output); try to break the new logic with your own repro scripts; check every acceptance criterion and edge case against code and tests (a criterion without a test that proves it is a finding); check the diff for secrets, accidental live-service calls, committed `.env`, and that the diff is only this ticket.
3. **Reviewers do not fix code** (only trivial typos/formatting). Independence matters: code fixed by its own reviewer is unreviewed. If anything is amiss: ticket Status `changes-requested` with precise findings, commit to main, stop and report.
4. If fine: open PR (title starts with backlog ID; body: summary, evidence, caveats, `Closes #N`, the 🤖 line), review the diff, `gh pr review --comment`, `gh pr merge --squash --delete-branch`, confirm the issue closed, set Status `merged` (or `blocked-foundation-merged` for owner-blocked tickets) with PR number and commands/results, commit and push memory.md to main.
5. Report: verdict, commands and results, findings, PR URL.

### M01 · Core schema: users, roles, profiles, children, locations, consent (#36)
- Status: **ready-for-review** on branch `m01-core-schema` (commit starts `M01:`; branch pushed, PR not opened). Blocked on owner only for applying anywhere real (see below).
- **Schema convention (M02/M03/M04 follow this):** one JSON file per domain in `appwrite/schema/` (`_base.json` = F02 runner table + CI sample table, `core.json` = M01). A ticket edits ONLY its own domain file (add `catalogue.json`, `scheduling.json`...). `appwrite/schema_build.py` validates every table and **generates** (a) the `tables` array of `appwrite/appwrite.config.json` (other keys stay hand-edited, so F04 editing `functions` does not conflict) and (b) `docs/erd/<domain>.md` (Mermaid). `--check` (default; also in `packages.json` lint for the appwrite package, so `make lint`) fails when generated files are stale; `--write` regenerates. If a rebase conflicts in a generated file, take either side and rerun `--write`. Domain file shape: `tables` (Appwrite CLI table objects without databaseId), `meta[table].deletion` in soft|history|immutable|join|hard (+ `note`), `relations` (`from: table.column`, `to`, optional `deferred` when the target table arrives in a later ticket). Validator rules: rowSecurity true; table `$permissions` empty (no any/users, no create/update/delete); required column cannot have a default (Appwrite; this caught F02's `sample_item.status`, now optional with default); varchar 1..16383, indexed varchar sum <= 768 chars, no text index, <= 64 indexes, one array column per index, row width estimate <= 65,535 bytes; `*_at` is datetime (UTC) and datetimes end `_at`; calendar dates are varchar(10) ISO; coordinates integer micro-degrees (`*_e6`); money-named columns integer; no float types; role enum values alphanumeric; every FK is varchar(36), indexed (first index column) and resolves to a table; soft tables need optional `deleted_at`; immutable tables have no deleted_at/revoked_at/updated_at.
